# プロジェクト生成ツール 仕様書

## 1. 概要

本ツールは、複数のテンプレートリポジトリを組み合わせて、用途に応じたプロジェクト初期構成を生成することを目的とする。

対象テンプレート例：

* Python_Template
* Git_Template
* Markdown_Template
* C_template

---

## 2. 設計方針

### 2.1 責務分離

* 各テンプレートは**独立したリポジトリとして維持**
* 本ツールは**統合・生成のみを責務とする**
* テンプレートの内容には依存しない（ブラックボックス扱い）

---

### 2.2 実行環境制約

* OS標準機能で実行可能であること

  * Windows：PowerShell
  * macOS / Linux：bash
* 追加ランタイム禁止

  * Python ❌
  * Node.js ❌
* 必須依存は以下のみ

  * Git

---

### 2.3 利用形態

| モード    | 説明        |
| ------ | --------- |
| 非対話モード | 引数でテンプレ選択 |
| 対話モード  | ユーザ入力で選択  |

---

## 3. 機能要件

---

## 3.1 テンプレート選択

### 要件

* ユーザは以下を選択可能とする

```text
git
python
c
markdown
```

---

### 選択ルール

* テンプレートの**自動付与は行わない**
* 指定されたテンプレートのみを統合対象とする
* 非対話モードでは、引数で明示されたテンプレートのみを対象とする
* 対話モードでは、ユーザが yes と回答したテンプレートのみを対象とする

---

### 振る舞い

* 重複は除去される

---

## 3.2 テンプレート取得

### 要件

* 各テンプレートは**GitHub上のテンプレートリポジトリから Git 経由で取得**する
* 取得時は **shallow clone**（履歴最小化）とする
* 本ツールの実行時は、ローカルコピーではなく GitHub 上の最新テンプレートを取得対象とする

---

### 非要件

* ローカルキャッシュは必須ではない
* `resources/000_originals` を本ツール実行時の取得元とすることは必須ではない

---

### 本プロジェクトでの参照ルール

* 本プロジェクトで実装・レビューを行う場合は、`resources/000_originals` を参照して仕様理解と整合確認を行う
* これは**本プロジェクトの開発時に限るローカル参照ルール**であり、生成スクリプト本体の取得元を固定するものではない

---

## 3.3 ファイル配置

### 出力先

* 統合結果は、実行ディレクトリ直下の `integlated` フォルダへ出力する
* `integlated` フォルダが存在しない場合は新規作成する
* 統合対象ファイルはすべて `integlated` 配下に配置する
* `integlated` フォルダが既に存在し、その中身が.gitignore以外にも存在する場合は、その旨をメッセージ表示して処理を中断する

---

### 基本ルール

1. 選択されたテンプレートのうち、**適用優先順位が最上位のテンプレートをベースとして適用**する
2. 残りのテンプレートを、優先順位に従って**追記・上書き**する
3. **選択されていないテンプレートは統合対象に含めない**

---

### 適用優先順位

```text
1. Git_Template
2. Markdown_Template
3. Python_Template
4. C_template
```

---

### ベーステンプレート決定ルール

* ベーステンプレートは、**選択されたテンプレート群の中で最上位のもの**とする
* 後続テンプレートは、上記優先順位に従って順番に追記する

---

### 適用例

```text
git + python
  → git をベースに python を追記

markdown + c
  → markdown をベースに c を追記

git + markdown + python + c
  → git をベースに markdown → python → c の順で追記
```

---

## 3.4 衝突検出

### 判定ルール

```text
1. ファイル未存在 → 追加
2. 完全一致 → スキップ
3. 差分あり → 衝突
```

---

### 衝突時の挙動

* 上書きは禁止（デフォルト）
* 以下を実施する

```text
<filename>.merge.<template>
```

---

### 出力例

```text
README.md.merge.python
.claude/CLAUDE.md.merge.c
```

---

## 3.5 ファイル種別ごとの処理ルール

---

### 3.5.1 機械的マージ対象

| ファイル           | 処理 |
| -------------- | -- |
| .gitignore     | 追記 |
| .editorconfig  | 追記 |
| .gitattributes | 追記 |

#### 追記ルール

* 追記は**テンプレート優先順位順**に行う
* 各テンプレート由来の追記ブロックの間には**空行を1行追加**する
* **重複行の削除は行わない**
* 出力ファイルの末尾には**必ず改行を入れる**

---

### 3.5.2 ドキュメント系

| ファイル | 処理 |
| ---- | -- |
| `intro_temp_git.md` | 追加 |
| `intro_temp_markdown.md` | 追加 |
| `intro_temp_py.md` | 追加 |
| `intro_temp_c.md` | 追加 |
| `README.md`（存在する場合） | ベーステンプレートを基準に追記 |
| `docs` 配下（存在する場合） | 追記 |

---

### 3.5.3 指示ファイル（重要）

| ファイル                             | 処理   |
| -------------------------------- | ---- |
| `.claude/CLAUDE.md`              | 衝突扱い |
| `.github/copilot-instructions.md` | 衝突扱い |

---

### 理由

* 意味的競合が発生するため
* 自動マージは不正確

### 要件

### 入力仕様

```text
Use Git template? (y/n)
```


## 4. 非機能要件

---

* OS依存を最小化
* bash / PowerShell双方で動作

### 4.2 安全性

### 4.4 可観測性

以下は本仕様の対象外とする：

* テンプレ内容の検証
* 自動3-wayマージ
* Git履歴の統合
* GUI

* 組み合わせの柔軟性

* 安全な衝突管理
